# CLAUDE.md

Guidance for Claude Code and other AI agents working in this repository. These rules override default behavior — follow them exactly. `agent-docs/` is the detailed reference for how the code behaves; this file is the rulebook and a map into it. `human-docs/` is the concise human guide.

## Rules

### Environment & tooling
- **Run everything in the Docker image.** The host has **no usable Python** (`import torch` fails). Every dependency lives only in the images: `halo:blackwell` (B200/B300, SM100/103, FA4+FA2, no FA3) or `halo:hopper` (H100/H200, SM90, FA2+FA3), built credential-free (`make build-blackwell` / `make build-hopper`) or pulled from Amazon ECR Public (`docker pull public.ecr.aws/whitecircle/halo:{blackwell,hopper}`: moving tags plus immutable `-$(VERSION)` pins, deliberately no `latest`, which would let a Hopper host pull a Blackwell image). On a host whose docker default runtime rejects `--gpus` (e.g. sysbox-runc), set `DOCKER_RUNTIME=nvidia` on any `make` target. Images are built with **uv** into the system interpreter — **no Poetry, no venv** — so `python`/`torchrun`/`accelerate`/`pytest`/`ruff` are on `PATH`; call them directly, no prefix. Dependency changes go through uv (`uv lock`, `uv pip install`; see `pyproject.toml` `[tool.uv]`). Standard detached launch ([Docker → Standard training launch](agent-docs/infrastructure/docker.md#standard-training-launch) explains each flag):
  ```bash
  # Resolve the scratch volume dynamically (see Preflight) — never hardcode a path.
  D=$(findmnt -rbno TARGET,AVAIL,FSTYPE | awk '$1!="/" && $3!~/tmpfs|overlay|squashfs|nfs|fuse|autofs/ && $2+0>20e9{print $2,$1}' | sort -rn | head -1 | awk '{print $2}')
  docker run -d --rm --name <job> --gpus all \
    --ipc=host --ulimit memlock=-1 --ulimit stack=67108864 --shm-size=128g \
    --cap-add=SYS_PTRACE --env-file .env \
    -e HF_HOME="$D/hf" -e HF_DATASETS_CACHE="$D/hf/datasets" \
    -e TMPDIR="$D/tmp" -e HALO_DATA_ROOT="$D" \
    -v $(pwd):/workspace -v "$D:$D" -v ~/.aws:/root/.aws -w /workspace \
    halo:blackwell \
    bash -lc "torchrun --nproc_per_node=8 <script> <config> > \"$D/<job>.log\" 2>&1"
  ```
  Provide your own repo-root `.env` (start from `.env.example`); it is **not auto-loaded** — pass it with `--env-file`. `HF_HOME`/`HF_DATASETS_CACHE`/`TMPDIR`/`HALO_DATA_ROOT` are a convention, not code defaults: point them at a verified large volume (the `make` targets read it from `HALO_SCRATCH`, resolved by the same filter when unset) — `/mnt` is **not guaranteed large**.
- **Launcher:** `torchrun` for all multi-GPU — EP/CP/TP/ETP/PP **and** plain FSDP2 data-parallel (`torchrun --nproc_per_node=N scripts/training/<script>.py <config>` lands on FSDP2 ZeRO-2); `python` for single-GPU/LoRA. `accelerate launch` + the `launcher-configs/accelerate/*.yaml` configs remain a supported option for plain FSDP data-parallel, but torchrun is the default. The `halo` CLI (`halo/cli.py`) picks the launcher — `halo launch <method> <config>`, `halo run <tool>`.
- **Preflight every run — disk, RAM, GPU.** Send large outputs, caches (`HF_DATASETS_CACHE`), and logs to a **verified** large mounted volume; the root FS is small and on some hosts shares a device with `/mnt`. **Check the target before any multi-GB write** (`df -h` / `findmnt` / `readlink -f` — a path's name does not prove its capacity). Before launching also confirm free host RAM and GPU health/free memory (`nvidia-smi`; `scripts/profiling/nvlink_health.py` for NVLink) — never launch onto a full disk, an OOM-prone host, or a degraded or already-occupied GPU. Scratch/temp markdown → `/tmp`.
- **Env vars.** `halo/env.py` is the single home for reading toolkit knobs (`HALO_`/`DIST_`/`VLLM_`/`SGLANG_`/`NVLINK_`) — one convention via `env_flag`/`env_int`/`env_float`/`env_str`, plus `HALO_DATA_ROOT` + `data_path()` for scratch. Route a new toolkit var through it, never a raw `os.environ.get`. Launcher (`LOCAL_RANK`/`SLURM_*`/`RANK`) and HF/OS vars are read raw at their owner by design; the `ACCELERATE_*` launch markers go through `is_accelerate_launch`/`is_accelerate_fsdp_launch` in `halo/env.py`. Full catalog with defaults (incl. `NVLINK_DOMAIN_SIZE`, the NVL72 locality unit): [Configuration Reference → Environment variables](agent-docs/reference/configuration-reference.md#environment-variables).

### Code style
- **Clean and professional — no slop.** No inline / function-local imports — the *only* exception is a genuinely optional or arch-specific dependency that may be absent at runtime (`flash_attn`, `deep_ep`, `deep_gemm`), marked `# noqa: PLC0415`. A **circular import is never that exception** — fix it structurally (move the shared symbol to a leaf module, or stop a package `__init__` from eagerly importing a heavy subpackage), never with a function-local import or a lazy-import wrapper. No duplicated logic, no hardcoded paths or per-run settings (a value a user sets per run reads config/env — `halo/env.py` is the home for env flags), no trivial function or class that only forwards to another, no sprawling or misplaced files, no papering over a root cause with a local patch. Reuse existing code, and put each thing where it belongs.
- **Names say what a thing owns.** A package is a domain noun or a plural collection; a module names the concept it owns. No module or package under `halo/`, and no module in `tests/common/`, carries a grab-bag or mechanism word as a whole `_`-separated token of its name — `utils`, `helpers`, `common`, `misc`, `core`, `mixins`, `patches`, `patching`, `wrapper`, `manager`, `shared`, `wiring`, `autograd`, `extension` (`shared_experts`, an MoE term, is fine). `base.py` holds only the abstract base its sibling modules implement. A package or module that still carries a banned word, or a `base.py` that is not an abstract base, takes no new module or concern; it is renamed when its package is restructured. Role words are class suffixes: `<Concept>Base` only on an abstract base, `<Concept>Mixin` only on a mixin.
- **One meaning per function prefix.** `is_`/`has_`/`supports_`/`uses_` predicate; `require_` returns the value it guards or raises (a field guard that checks a config in place returns `None`); `reject_` refuses an unsupported request (raises, returns `None`, mutates nothing); `validate_` raises on a malformed value, and its docstring states any normalization it applies; `verify_` raises when built state (loaded weights, a live model, the host) differs from what the run assumed; `resolve_` derives a value; `get_` reads one without deriving; `find_` returns `None` on a miss; `named_` returns (name, object) pairs; `build_` constructs (no `make_`; `create_` only makes a filesystem entry); `apply_` mutates a model or run, `install_` wraps or hooks, `ensure_` makes a process-wide condition hold, each idempotently; `patch_` replaces a third-party symbol; `register_` adds to a registry or hook table; `configure_` is run setup; `load_` reads a model or weights, `save_` writes, `restore_` reads saved state back on resume; `warm_` precompiles; `agree_`, `gather_` and `*_across_ranks` name a collective, while `merge_` combines parts already in hand. An override keeps the name its third-party base defines (`create_optimizer`, `get_train_dataloader`, `named_parameters`).
- **Name a value only when it is shared, tunable (a budget, size or threshold a developer adjusts), serialized, test-pinned or opaque** (meaningless as a bare literal); everything else stays an inline literal. `UPPER_SNAKE` is for immutable values only; mutable module state is lowercase and reached through a public object or function. A `_private` name stays in its module: nothing else under `halo/` imports it. No mirror constants: a default reads the config class, a choice list comes from `get_args` on its `Literal`, and a hand-kept map keyed by a `Literal` carries a test that its keys are exactly that `Literal`'s values.
- **Good file structure.** Lay a module out top-down: docstring → imports → logger → immutable constants → mutable module state → types → functions and classes, each private helper defined before its first user (a constant built from a type or helper of the module goes just after it). In a class body: class attributes, then `__init_subclass__`/`__init__`, then public methods and properties in lifecycle order, then private helpers below their first caller. Group related code and place a file in the package that owns its concern; don't bury a definition mid-file.
- **Comments and docstrings are sparse and load-bearing.** A module docstring says what the module owns, in five lines or fewer. A function docstring states the contract — a collective says so first, then what it returns and raises — plus at most one non-obvious *why*; a comment explains a non-obvious *why* at the line it governs, never in a long block. Neither narrates what the code plainly does, lists callers or consumers, justifies where a module sits or what it may import, restates a roster a registry derives, or tells stories (past runs, "previously X", "was broken then fixed", dated notes) — that history belongs in git, not in source. An error message gives the mechanism and the remedy and names symbols, not source paths.
- **One logger form.** A module binds `logger = logging.getLogger(__name__)` (`info_logger(__name__)` only where it needs its INFO pin), never accelerate's or transformers' `get_logger`; a line for global rank 0 only is guarded at its call with `if is_global_main_process():` (`halo/runtime/ranks.py`), never by a logger keyword.
- **Derive from the class hierarchy or a registry** — a per-class attribute the base unions over registered subclasses, polymorphism or a registry — never a hand-maintained list or a `model_type ==` string-ladder that duplicates what a class already knows.
- **Generalize to the whole roster** (dense + every MoE family) and to large scale, while **avoiding over-engineering** (no gold-plating, no speculative abstraction, no registry where branches are genuinely distinct).
- **Fail loud** over a silent fallback that hides a real error.
- **Refactors must be behavior-preserving and proven so** — ruff + in-image tests, ideally an equivalence check — before they land.
- **Hold the whole matrix in mind** before landing anything load-bearing: all parallelism modes (EP/CP/TP/ETP/PP + combinations, incl. `ep_group_size==1`+`fsdp_shard_ep1_experts` DTensor experts vs `ep_group_size>1` (EP or pure ETP) FSDP-ignored plain tensors), multi-node topologies (node-local vs cross-node EP, NVLink domains, PP stages across domains, shared vs non-shared FS, deferred cross-node DP), and every supported model (each MoE family has its own expert layout/gather). A change correct for one model/single-node/dense-FSDP can silently break another (a plain-vs-DTensor `copy_`, a collective that must run on every rank, a per-family interleave, a non-shared-FS writer race). Prefer model-agnostic, sharding-agnostic seams.

### Docs & markdown
- **Docs first.** Check `agent-docs/` (the detailed AI reference) before searching the code; only read `halo/` directly if the docs don't answer it. `human-docs/` is the concise human guide.
- **Markdown only in `agent-docs/`** (detailed reference), **`human-docs/`** (human guide) **and `skills/`** (agent skills; `.claude/skills` and `.agents/skills` are symlinks to it for Claude Code and Codex discovery). Root GitHub-convention files (`README.md`, `CONTRIBUTING.md`, `SECURITY.md`, `CODE_OF_CONDUCT.md`, `AGENTS.md`, `CLAUDE.md`, `.github/**`) are the exception. Never create `.md` elsewhere; scratch/design notes go to `/tmp`, not the repo.
- **One home per fact.** Each fact lives on one owner page and every other page links it instead of restating it; this file keeps only the one-line rules an agent must not miss, each linking its owner. A configuration field's type and default are tabled only in `agent-docs/reference/configuration-reference.md`.
- **Keep docs current.** A significant `halo/` change updates its owning doc page (ownership map: `skills/docs/docs-ownership.md`). Docs follow the lean **present-state** style charter (`skills/docs/style.md`, via the `docs` skill): load-bearing facts only, no changelog/story-telling, cite sparingly. All doc trees are plain GitHub-rendered markdown (no build); run `./scripts/docs/check_links.sh` (or `make docs`) after edits to keep relative links, heading anchors and code references valid (`{#id}` heading attributes are refused — GitHub does not render them).

### Process
- **Read code thoroughly before changing it.** Don't judge from an isolated grep hit — read whole files when they aren't too large, and follow definitions and references through the call graph to understand the actual logic and its callers.
- **Use multiple agents, often — it's the default, not the exception.** For any substantive investigation, audit, review, or refactor, fan out several **disjoint-scoped** subagents (Explore / general-purpose) that work in parallel, then **adversarially self-review** — verify every finding against the actual code and runtime data (agents can be wrong), and read their diffs yourself before accepting.
- **Verify before calling it done.** After a code change, run ruff and the in-image tests it touches, confirm it complies with these rules (no slop, holds across the parallelism/model matrix), and prefer an independent review pass — a fresh agent checking correctness and rule-compliance — on anything load-bearing.
- **Fix root causes,** not symptoms — state the mechanism, then fix it (not "lower the LR" around a drift).
- **Finish the user-facing path, not just the guard.** Every supported configuration owes the user a complete path: train → resume → **export/serve**. Turning a silently-wrong artifact into a loudly-unusable one is half a fix — if the change leaves a checkpoint no tool accepts, close that gap in the same change instead of documenting the dead end. A trainable artifact nobody can serve is not a deliverable, and "only the guard was asked for" is not a reason to ship one.
- **Sensitive areas need explicit, informed approval.** The paths listed in `.github/sensitive-paths` (grouped by concern there) are never changed on an agent's own initiative or on a blanket "go ahead". Before touching them, lay out the mechanism, the blast radius across the parallelism/model matrix, and what a re-lock or image rebuild implies, then get the user's explicit approval of *that* account — their go-ahead has to show they understand what changes and why; a bare "do it" is not approval here. That file is the one list: a change that moves or deletes a listed path, or gives sensitive code a new home, updates it in the same change. Elsewhere the normal rules apply.
- **Contribution gate + bar** ([CONTRIBUTING.md](CONTRIBUTING.md#the-gate-read-first)): Halo is a **public, gated** project — every change starts as an accepted **issue**, a maintainer must comment `/approve @your-handle` on it **before** any PR, and PRs from anyone not approved (without write access) are **auto-commented and closed** by `.github/workflows/pr-gate.yml`. **Any coding agent working in this repo must respect that gate** — do not open a PR off an unapproved path. The bar: own every line, disclose the AI scaffold + models in the PR, keep diffs under ~2,000 lines, sign every commit, and write tests that **fail when the behavior breaks** (no tautological / smoke-only / vacuous assertions).

## Project

Halo is an LLM alignment toolkit that extends HuggingFace (Transformers, TRL, Accelerate) with Expert / Context / Tensor / Expert-Tensor / Pipeline Parallelism and training methods from SFT and pretraining through preference (SMPO, DPO, KTO), the GRPO family (offline, online, async with environments), distillation, reward, classification and embedding. It trains dense models and every MoE family in the [compatibility matrix](agent-docs/models/README.md#compatibility-matrix) (EP via DeepEP), Qwen3-Next included and Qwen3.8-Flash-Next as experimental, multi-node, with multi-turn RL on Ray actors; datasets come from the HuggingFace Hub, local paths or S3 (`s3://`, your own credentials).

**Stack:** Python 3.12 · uv (`pyproject.toml` + `uv.lock`) · PyTorch ~2.11 (+cu130) · Transformers ~5.20 · TRL ~1.14 · Accelerate ~1.11 · PEFT ~0.18 · Liger ^0.8 · FlashAttention-4 4.0.0b37 (Blackwell, beta). Base image NGC `nvcr.io/nvidia/pytorch:26.03-py3` (Ubuntu 24.04, CUDA 13.2).

**RL serving:** vLLM 0.32.0 and SGLang 0.5.22 run as **separate** containers (`Dockerfile.vllm` / `Dockerfile.sglang`, built as `halo:vllm-0.32.0` / `halo:sglang-0.5.22` by `make build-vllm` / `make build-sglang` and published under those tags, run by `docker-compose.{vllm,sglang}.yml`); the trainer pushes weights over NCCL through `halo/weight_sync/` and never imports either engine (ABI-incompatible stacks). Sync holds only on these images with the compose flag `--moe-backend triton` (SGLang: `--moe-runner-backend triton`). The vLLM build asserts its sync patches (layerwise-reload skip set, weight-transfer re-init), the `/pause` `mode=keep` route and the split top-p guard, and its pinned Model Runner V2 carries thinking budgets and R3 capture (never set `VLLM_USE_V2_MODEL_RUNNER=0`): [Rollout Servers → vLLM server patches](agent-docs/infrastructure/rollout-servers.md#vllm-server-patches). A family an engine cannot update (`UNSERVABLE_MODEL_TYPES` on its client, `weight_sync_refusal` on the family spec) is refused at trainer construction ([Which families each engine serves](agent-docs/infrastructure/rollout-servers.md#which-families-each-engine-serves)).

**Layout:** one package, `halo/`. Its layers run from L0 `env` to L10 `entrypoints`, and a unit imports only from strictly lower rows (`tests/cpu/conventions/test_import_layering.py`): [Architecture → Layer table](agent-docs/reference/architecture.md#layer-table), whose component map is the module map; `skills/docs/docs-ownership.md` maps each `halo/` path to its owner page. `scripts/` holds the entry points by pipeline stage (`training/`, `inference/`, `before_training/`, `after_training/`, `profiling/`, `environments/`) while the drivers stay in `halo/`; recipes live in `examples/<method>/<family>/`.

**Debug/profiling:** `enable_torch_profiler: true` (per-rank traces, EP phases labeled), `halo run trace-report` (TraceLens workbooks), `halo run py-spy-diag` (keep the recipe's `--cap-add=SYS_PTRACE`) and the torch-free `halo run nvlink-health` preflight — [Debugging](agent-docs/reference/debugging.md). **When a run fails** (config rejection, NCCL hang/timeout, OOM, DeepEP fault), start at [Troubleshooting](agent-docs/reference/troubleshooting.md).

## Parallelism

`data_parallel_size = world_size / pp_size / max(cp_size, tp_size, expert_tp_size)` ([Stacking the dimensions](agent-docs/parallelism/README.md#stacking-the-dimensions)). Which axis sets may run at all is an **allowlist** (`SUPPORTED_AXIS_SETS`, `halo/distributed/parallelism_rules.py`) checked at config time before any rank math; the supported combinations and DP size per mode are in [Supported combinations](agent-docs/parallelism/README.md#supported-combinations), the locality and composition rules in [Topology rules](agent-docs/parallelism/README.md#topology-rules), the per-family verdicts in the [compatibility matrix](agent-docs/models/README.md#compatibility-matrix), and trainer × CP/PP in [Trainer compatibility](agent-docs/reference/trainer-architecture.md#trainer-compatibility).

**Single-domain pure EP (the costliest mistake):** on one NVLink domain, `ep_size > 2` with `ep_group_size < nvlink_domain_size` (ep4 on 8 GPUs) is **rejected at config time** — the DeepEP combine barriers race FSDP2's DP-wide NCCL. Use `ep_size == 2`, raise `ep_size × expert_tp_size` to the domain (EP+**ETP** for 4-way+ sharding), or shrink the job; attention TP leaves `ep_group_size` unchanged, so ep4+tp2 is refused too. The unit is the NVLink domain (`NVLINK_DOMAIN_SIZE` on NVL72), not the OS node ([mechanism](agent-docs/parallelism/expert-parallelism.md#single-domain-multi-group-ep-races-and-hangs)).

**Add a method:** config class in `halo/configs/` → subclass `DistributedTrainerMixin` in `halo/trainers/<family>/` → script in `scripts/training/` → YAML in `examples/` → tests in `tests/`. Scripts parse through `parse_script_args`, which starts the process group and sets `FLASH_ATTENTION_DETERMINISTIC` for a `full_determinism` config before anything picks an attention backend ([Parsing](agent-docs/reference/configuration-reference.md#parsing)). Trainer `__init__` does `kwargs = self._init_distributed_config(kwargs, ctor_args=args, ctor_positions=_CTOR_POSITIONS)` then `super().__init__(...)` then `self._configure_distributed_modes()` ([Trainer Architecture → Lifecycle](agent-docs/reference/trainer-architecture.md#lifecycle)). CP and PP are declare-to-enable (`SUPPORTS_CP`, `PP_REFUSAL`); nothing inspects a trainer's loss for CP- or PP-safety, so a new trainer verifies its own objective before declaring either.

## Key facts

- **Reshard before reading parameters.** Anything that reads parameters outside a forward — the optimizer build, every checkpoint writer, `save_model`, RL weight sync — calls `reshard_fsdp2_modules` first: a forward leaves transient unsharded params registered while the optimizer steps the shards ([Data Parallelism](agent-docs/parallelism/data-parallelism.md#how-the-mixin-manages-fsdp)).
- **Replicas start from one copy.** FSDP2, unlike DDP, broadcasts no module state and replicas average only their gradients, so the wrap gives every HSDP replica the first one's shards and every FSDP-ignored whole copy at `ep_group_size == 1` DP rank 0's, and QLoRA starts every floating-point parameter from rank 0's ([Data Parallelism → HSDP](agent-docs/parallelism/data-parallelism.md#hsdp-hybrid-sharded-data-parallel)); the copies several EP groups hold of one parameter (expert shards, and non-expert shards under deferred DP) still rely on every rank being seeded alike, as the entry scripts seed them ([Expert Parallelism → Limitations](agent-docs/parallelism/expert-parallelism.md#limitations)).
- **FSDP2 under reentrant checkpointing.** Every rank runs each decoder layer the same number of times per backward: a layer recomputed more than once gets FSDP2's post-backward hook only once, and the trainer completes every shard group after each backward and raises on one left undone (`complete_fsdp2_post_backward`) ([Data Parallelism → Layers recomputed more than once per backward](agent-docs/parallelism/data-parallelism.md#layers-recomputed-more-than-once-per-backward)).
- **Exact resume fails loud.** An interrupted save, or an optimizer restore that passes the fingerprint gates and still fails, raises on every rank unless `allow_optimizer_warm_restart: true`; a step directory without `trainer_state.json` (published last) is incomplete, and `resume_from_checkpoint: true` passes over it ([Checkpoints → Warm restart vs exact resume](agent-docs/reference/checkpoints.md#warm-restart-vs-exact-resume-torchrun)). An adapter resume (`restore_adapters`) checks the file against the live adapters key for key and shape on every rank before any copy ([Checkpoints → Resume by parallelism mode](agent-docs/reference/checkpoints.md#resume-by-parallelism-mode)), and a run that grew its vocabulary (`vocabulary_grown`) saves and restores the added embedding rows with its adapters ([Checkpoints → PEFT (LoRA) saving](agent-docs/reference/checkpoints.md#peft-lora-saving)).
- **Non-finite steps are never applied** (`halo/trainers/step_guard.py`): AdamWBF16 and Muon skip a NaN/inf-norm step on the device and the host reads the verdict one step late, so a streak's raise fires one step later ([Trainer Architecture → Non-finite steps](agent-docs/reference/trainer-architecture.md#non-finite-steps)).
- **EP expert export** — gathered saves, `scripts/after_training/merge_ep_shards.py`, engine weight sync — writes each family's one `ExpertLayout` (`MoEFamilySpec.expert_layout`, applied by `to_hub_expert_tensors`); a new family declares its layout, not a gather of its own ([Adding a Model → Add EP support](agent-docs/models/adding-a-model.md#add-ep-support)).
- **Attention** auto-selects FA4 on Blackwell and FA3 on Hopper, FA2 where neither imports, and narrows that per family and per row shape (FA4's head_dim-256 kernel and its deterministic backward, latent attention, softcaps, prefix LMs such as PaliGemma, multi-document rows, the padded scripts) as [Flash Attention → Model-specific handling](agent-docs/optimization/flash-attention.md#model-specific-handling) lists; SDPA never runs a softcapped model, and no flash kernel a prefix LM, whose mask lives in `token_type_ids`. GptOss sinks are neutralized for SFT (`reset_sinks: true`) and kept live for on-policy RL, which admits only sink-carrying implementations ([GPT-OSS → Attention sinks](agent-docs/models/gpt-oss.md#attention-sinks)).
- **Multi-document rows** (`packing`, `padding_free`) are refused wherever a layer would cross documents silently, unless `allow_cross_document_linear_attention: true` accepts Ring's unmarked linear attention or Inkling's short convolutions, which pipeline parallelism never does; GLM-5 Next packs only as tree rows, which pipeline parallelism refuses ([Collators → Document isolation under packing](agent-docs/data/collators.md#document-isolation-under-packing)).
- **EP requires DeepEP** (V2 in the images; no NCCL fallback); never install `nvidia-nvshmem-cu12` over the cu13 stack ([DeepEP](agent-docs/infrastructure/deepep.md)).
- **Never let a kernel compile or load mid-run.** A first launch that compiles (Triton, FlexAttention, FA4) or lazily loads (a CUDA module, a CUTLASS tile) after the warm-up stalls every peer in the next collective, or inside DeepEP's barrier between a dispatch and its combine: warm it at load (the EP warm-up, `warm_attention_kernels`) or key it so a step's shape selects no new variant (the fused AdamWBF16 table) ([Expert Parallelism → Kernels](agent-docs/parallelism/expert-parallelism.md#kernels)). GptOss's expert-bias GEMM is the known exception: cuBLAS picks its kernel by the receive's length ([Expert Parallelism → Limitations](agent-docs/parallelism/expert-parallelism.md#limitations)).
- **Gather to rank 0 over the ring** with `gather_on_rank0` / `combine_across_ranks` (`halo/runtime/collectives.py`), never `dist.gather_object` or point-to-point sends on the default NCCL group: NCCL connects every peer to rank 0 and keeps those buffers, about 0.3 GiB per NVLink peer, for the rest of the run ([Architecture → Component map](agent-docs/reference/architecture.md#component-map)).
- **fp32 matmul precision** is pinned to `highest` at model load (`configure_float32_matmul_precision`, knob `HALO_FP32_MATMUL_PRECISION`): the NGC image's TF32 default collapses adjacent RoPE positions past 2048 and silently corrupts long context ([Configuration Reference → Environment variables](agent-docs/reference/configuration-reference.md#environment-variables)).
- **Model loading:** every path that materializes weights — the distributed loaders and any `scripts/` tool whose model reaches a forward — ends in `finalize_loaded_model` (`halo/model_loading/finalization.py`): it repairs the non-persistent buffers transformers re-materializes as uninitialized memory, sets FLA's launch options (`apply_fla_launch_options`, which keeps the delta rule's state kernel on its `num_warps=2` configs on Blackwell) and attaches a family's external tables (Qwen3.8-Flash-Next's n-gram table) ([Adding a Model → Add EP support](agent-docs/models/adding-a-model.md#add-ep-support), step 6).
- **Elsewhere:** read [Levers that do not help at these shapes](agent-docs/optimization/README.md#levers-that-do-not-help-at-these-shapes) before tuning throughput; router balancing and its `bias_update` export contract live in [Callbacks → MoE balancing modes](agent-docs/training-methods/callbacks.md#moe-balancing-modes), checkpoint-tool flags in [Scripts → Post-training scripts](agent-docs/reference/scripts-reference.md#post-training-scripts), per-family quirks on the [family pages](agent-docs/models/README.md#per-family-pages).

Everything else starts at [agent-docs/README.md](agent-docs/README.md) (the agent index) or [human-docs/README.md](human-docs/README.md) (the human guide).
