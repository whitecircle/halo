# Metrics and Troubleshooting

Async GRPO metrics are namespaced by the question they answer. Rollout means are over the gathered episode population, and the `sampling/*`, `reward/*` and `routing/rollout_*` fractions and means fold every rank's counts in one collective per step, so neither is one rank's shard. The `async/prefetch_*` counters and `routing/replay_flip_rate` sum every rank's counts at each log line.

## Logged metrics

| Namespace | Answers | Keys to watch |
|---|---|---|
| `async/*` | rollout throughput | `mean_rollout_latency`; job totals `total_rollouts`, `cumulative_mean_rollout_latency`, `total_generation_tokens`; `prefetch_hit_rate`, `prefetch_hits` / `prefetch_misses`; `requests_expired_in_sync` |
| `episode/*` | agent behavior | `turns`, `generation_tokens` (+`_max`, `_p90`), `natural_termination_rate`, `truncation_rate`, `truncation_alarm`, `error_rate`, `length_cutoff_turns`, `length_cutoff_in_call_turns`, `empty_turns`, `output_budget_exhausted`, `reasoning_cjk_rate`, `tool_calls`, `sandbox_infra_fault`, `sandbox_agent_fault`, `reward_scored` |
| `outcome/*` | task success | `solve_rate`, `all_pass_group_frac` / `all_fail_group_frac`, eval `success@k`, plus per-env keys such as `test_pass_frac` |
| `reward/*` | reward and decomposition | bare `reward` / `reward_std`; `within_group_std`; the components `turn_shaping`, `tool_shaping`, `objective`, the environment's own terms (`submission`, …) and each external term's `<name>`; `composition_residue`; the trainer's `reasoning_price`, `reasoning_floor`, `turn_overlong` and `turn_overlong_turn_frac` (the share of assistant turns the overlong charge charged) |
| `judge/*`, `reward_model/*` | external reward terms | `judge/<name>/<requirement>` or, for a veto judge, `judge/<name>/<check>`, `judge/<name>/veto`, `judge/<name>/unsupported_flags`; `judge/<name>/completion_tokens`, `judge/<name>/cost_usd`, `judge/<name>/scored`; `reward_model/<name>/logit`, `reward_model/<name>/scored` |
| `logps/*` | policy confidence | `sampling_mean`, `advantage_cov`; the related `kl`, `entropy`, `kl_clamp_frac` are unnamespaced |
| `advantage/*` | the round's push on the sampled tokens | `net_token_mass` (before balancing), `token_mass_scale` (under `balance_token_mass`), `negative_only_mass` (the untrainable turns' share, the net push it leaves on the other rows) |
| `sampling/*` | engine/trainer agreement | `is_correction_active`, `logratio_mean`, `is_ratio_mean` / `is_ratio_max`, `is_ratio_extreme_frac`, `is_ess_frac`, `is_correction_coverage`, `is_masked_frac`, `sampler_certain_frac`, `update_skipped`, `degenerate_group_frac`, `invalid_episode_frac`, `rows_over_cap_frac`, `forced_close_frac`, `untrainable_rows_frac`, `untrainable_rows_trained_frac`, `untrainable_turns_rowless_frac` |
| `routing/*` | MoE routing replay | `replay_flip_rate`; under R3, the shape classes `rollout_full_frac`, `rollout_engine_omits_last_frac`, `rollout_completion_only_frac`, `rollout_unresolved_frac` (the one that says replay is degrading; a rank whose routed rows are all unresolved fails the step), plus `rollout_prompt_len_mismatch_frac`, which sits outside their denominator |
| unnamespaced | TRL loss internals | `clip_ratio/*`, `cispo_clip_ratio` (under `loss_type: cispo`), `step_time` |

`async/prefetch_*` appears only with multiple servers; `prefetch_input_skips` only once non-zero — a wedged prefetch worker dropped those prompts and they never trained. `async/requests_expired_in_sync` is a count per rollout round across the world, not a mean: the request deadlines that ran out on a request in flight across a weight sync even with the pause credited. Each threw away a turn the engine had already started (retried, or ending its episode on the last try), so nonzero means `request_timeout` is too tight for the backlog a sync leaves. `episode/output_budget_exhausted` appears only under `rollout_max_episode_tokens`: the fraction of episodes whose output budget no longer held a turn's answer room — ended there truncated, or done with no room for another turn ([Trajectory length](rollouts.md#trajectory-length)). Task-specific `outcome/*` and `reward/*` components come from the environment's `rollout_metrics` hook.

Under `sampling/*`, `is_correction_coverage` is the share of loss tokens the engine's sampling log-probs cover, `is_masked_frac` the share of those a mask stage zeroed, `is_ratio_mean` / `is_ratio_max` the surviving ratios, and `sampler_certain_frac` the policy tokens the engine emitted with probability 1, which carry no correction, except a forced reasoning close, which gets ratio 0 (`forced_close_frac`, over the tokens that carry sampling log-probs, as `sampler_certain_frac` is). `is_ratio_extreme_frac` is the share of corrected tokens whose raw trainer-vs-sampler ratio lies outside `[1 / vllm_importance_sampling_clip_max, vllm_importance_sampling_clip_max]`, counted like `logratio_mean` over every corrected token before any mask or drop. `is_ess_frac` is the normalized effective sample size `(Σw)² / (n Σw²)` of the IS weights the loss applies over the corrected loss tokens, masked ones counting as zero: 1 when every weight is equal, falling as a few tokens carry the correction.

Four more diagnostics read the step without changing it. `outcome/all_pass_group_frac` and `outcome/all_fail_group_frac` split the groups by the environment's solve verdict (the one behind `solve_rate`; absent where the environment reports none): a group every valid member solved carries no objective signal, one none solved carries only the shaping terms, and the two say whether the task is too easy or too hard; groups whose settled environment rewards are all equal are `sampling/degenerate_group_frac`. `logps/advantage_cov` is the covariance, over the loss tokens, of each token's log-prob under the pre-update policy and its advantage; it pools tokens from different contexts, so its sign need not match the direction `entropy` moves. `advantage/net_token_mass` reads that direction under a token-sum loss (`dapo`, the default here): a share that stays negative (failures longer than solves) pushes entropy up, one that stays positive pushes it down ([Advantages](objective.md#advantages)). `episode/truncation_alarm` is 1 in a round whose `episode/truncation_rate` is over [`truncation_alarm_rate`](../../../reference/configuration-reference.md#asynctrainingconfig), which also warns when the rate first crosses it.

Every episode's categorical facts slice the metrics: its resolved effort level under `effort/<level>/*`, and any string an environment stamps under `trajectory.info["slices"]` as `<slice>/<value>/*`. Code-contests stamps the language of the last tool call where the run offers a choice of them, giving `language/cpp/*`.

Each slice carries `count`, `reward`, `generation_tokens`, `reasoning_tokens`, `turns`, `truncation_rate` and `solve_rate`, plus the environment's own `episode/*` keys with that prefix dropped (`effort/high/test_calls`). With the overlong charge on, `effort/<level>/turn_overlong` and `effort/<level>/turn_overlong_turn_frac` split it by level.

Step timings land under `profiling/Time taken: <Trainer>.<name>` (main process only). The trainer adds `rollout_acquire` (the generation wait, near zero on a prefetch hit), `build_training_tensors` and `weight_sync`.

## Reading the metrics

Four common misreadings:

- **`reward_std` is not the learning signal.** It is the sample std over the gathered **valid** episodes, dominated by between-problem difficulty spread. `reward/within_group_std`, the mean of each group's reward std (0 for a group with fewer than two valid episodes), is what the advantage uses: near zero means degenerate groups and no gradient ([Advantages](objective.md#advantages)).
- **`episode/natural_termination_rate` is not a solve rate.** That is `outcome/solve_rate` (code contests; other environments report only `reward`). It is the fraction that reached `done` without truncation, and says nothing about turns the engine cut at their token cap — those are `episode/length_cutoff_turns` ([Reasoning budget](rollouts.md#reasoning-budget)).
- **Two episode-health signals a termination rate hides.** `episode/empty_turns` counts the turns the model ended with neither a tool call nor visible content — a stop inside its reasoning, below the cap — which recover like cuts ([Reasoning budget](rollouts.md#reasoning-budget)). `episode/reasoning_cjk_rate` is the fraction whose reasoning drifted into CJK script.
- **The decomposition separates objective from shaping.** `reward/objective` is the environment's grade priced by its term; `reward/turn_shaping` and `reward/tool_shaping` are the per-turn and episode-level shaping, and the environment's own terms and each `judge` / `reward_model` term log by name ([Reward Terms](../rewards.md#environment-arm)). In every environment the components sum exactly to the environment's settled reward per episode (the headline `reward` adds the trainer's `reward/reasoning_*` and `reward/turn_overlong` charges and averages valid episodes only); `reward/composition_residue` is the mean absolute gap, and nonzero means a channel bypasses them. A rising `reward` means task progress only when the objective component moves. `episode/reward_scored` below 1 means a judge or reward-model call reached no verdict, and `<source>/<name>/scored` names the term: it scores 0 either way, and the episode leaves the baseline as invalid under the term's `on_error: invalid` (the default; `neutral` for a veto judge) or stays valid and trains on its other terms under `neutral`. `judge/<name>/veto` is the share of judged episodes a veto check fired on, stripping their credits ([Reward Terms](../rewards.md#outages)).

`reward`, `reward_std` and `reward/within_group_std` cover the **valid** episodes only — the rows that train; `sampling/invalid_episode_frac` reports the rest ([Batch construction](objective.md#batch-construction)).

## Early stop

Off unless a condition is set. Each condition counts its breaching readings in a row (a reading is one training log line, the window's mean under `logging_steps` > 1; the gap and the breaker's verdict come once per generation round, so a step reusing its round carries neither and leaves their count), and once one reaches `early_stop_patience` (default 3) training ends there, without saving or evaluating that step (an epoch save included): the stop logs its reason, the script exits non-zero on every rank naming the step it stopped at, and the run resumes from a checkpoint taken before the drift began. The verdict is taken across ranks.

| Knob | Stops when | Reads |
|---|---|---|
| `early_stop_entropy_band` | `entropy` stays outside `[low, high]` | TRL's `entropy` |
| `early_stop_logratio_gap` | the trainer-vs-sampler gap stays above it | the magnitude of `sampling/logratio_mean`; needs the IS correction |
| `early_stop_on_skipped_updates` | the breaker skipped every update | `sampling/update_skipped`; needs `skip_update_masked_frac` |

TRL's `entropy` is a mean of per-micro-batch means over the loss tokens, and it counts a micro-batch whose loss tokens were all dropped (degenerate groups, invalid episodes, padding rows) as 0. Under drops it therefore reads below the policy's entropy, and it moves with the dropped share as well as with the policy.

The band and the gap are model-specific: read them off a healthy run. A drift shows in the gap before it shows in entropy, since the gap grows faster than entropy once the policy flattens. The Qwen3.6 vLLM code-contests recipes stop on a band of `[0.12, 0.40]` and a gap of `0.005`; every code-contests recipe stops on skipped updates. Online GRPO takes the band and the gap ([Online GRPO](../online-grpo.md)).

## Evaluation

Eval metrics carry the `eval_` prefix. The eval group size is `num_generations_eval` (TRL's `GRPOConfig`, `None` → `num_generations`); set it to `1` for a fast pass@1 monitoring eval. Under `reasoning_effort: random` each problem's level is drawn from its text, so every eval round scores a problem at the same level and checkpoints compare level for level. Above 1, and where the environment reports a solve verdict, `eval_outcome/success@<k>` is the share of prompts any of their `k` valid samples solved; `eval_outcome/solve_rate` stays the per-sample mean.

Eval rounds run without prefetch and a round waits for its slowest episode, so `eval_rollout_batch_size` widens the round — rows per rank, not prompts. It must be a multiple of `num_generations_eval`, at most `max_concurrent_rollouts`, and needs `dataloader_drop_last: false` — all three raise at startup ([`eval_rollout_batch_size`](../../../reference/configuration-reference.md#asynctrainingconfig)). Every rank runs the same rounds, so a split that leaves the last round short is padded with repeats of its first rows. The repeats are never rolled out and no rollout metric or completions row counts them: each problem counts `num_generations_eval` times. TRL's loss-time eval metrics (`eval_entropy`, `eval_clip_ratio/*`, `eval_kl`) are rank means, so a rank whose whole final round is padding adds a 0 to that round. A logged eval metric is the mean of its per-round values, each round weighing the same however full it is: for an exact mean, make `len(split) × num_generations_eval` a multiple of `eval_rollout_batch_size × data_parallel_size`, or, for the rollout metrics, run the split in one round.

Left unset, one round is one eval batch, and the same check then requires `per_device_eval_batch_size` to hold whole groups. The loss forward chunks by it either way.

## Troubleshooting

| Symptom | Cause | Fix |
|---|---|---|
| `entropy` climbing for tens of steps, reasoning shrinking, `sampling/logratio_mean` widening until `sampling/update_skipped` holds at 1 | A KL-free run whose failures outlast its solves: `advantage/net_token_mass` stays negative and each step pushes down the sampled tokens | `balance_token_mass: true`; arm the [early stop](#early-stop) and resume from the last checkpoint before the drift |
| `server unreachable at …`, or a stall in `init_communicator()` | The server is not serving, or never joins the NCCL group: an unroutable advertised master, or trainer and server on one GPU | Verify `/health`; set `VLLM_GROUP_HOST` / `SGLANG_GROUP_HOST` to a routable NIC; give them different `CUDA_VISIBLE_DEVICES` ([Rollout Servers](../../../infrastructure/rollout-servers.md#troubleshooting)) |
| `Could not bind the weight-transfer group port` | Another socket holds the configured port: a live client or process, or an outbound connection given it as its source port (a port inside the ephemeral range). `SO_REUSEADDR` rules out `TIME_WAIT`. Raised before the server is asked to join, so the server keeps serving | Give each server and trainer its own `group_port` / `vllm_group_port`, outside `net.ipv4.ip_local_port_range` or reserved; remove the stale container |
| `GENERATION is wedged (no response … to a 1-token probe)` | `probe_generation` found a scheduler stuck after a trainer died mid-sync | Restart the server container after every hard trainer crash |
| `vLLM server … is PAUSED for a weight update` | A trainer died without lifting its `/pause` | `POST /resume`; restart the server instead if that sync had already streamed part of the model |
| `Prefetch auto-disabled: 1 rollout server configured.` | Expected: a sync pauses the only server | Configure more servers ([Multiple servers and prefetch](setup.md#multiple-servers-and-prefetch)) |
| `DeadlineExpired: request exceeded its …s deadline` | Server overloaded or wedged; a weight-sync pause is already excluded. Actors retry with backoff (`request_timeout` 120 s, `max_retries` 3, `retry_base_wait` 1 s) | Check server health first; 4xx are terminal except 408 and 429 |
| Episodes booked into `episode/error_rate` near `episode_timeout` | The whole episode — generation, tools, grading — passed its deadline (default 1200 s) | Raise `DIST_NCCL_TIMEOUT_MINUTES` first, then `episode_timeout` ([bounds](performance.md#sizing-a-run)) |
| `404 … "The model <path> does not exist"` on every rollout | `model_name` is unset by default and filled with `model_name_or_path`, so a checkpoint path is sent as the id | Set `model_name` to the id at `/v1/models`, or serve with `--served-model-name` |
| `500 "Already borrowed"` | A vLLM fast-tokenizer race that scales with concurrency | Harmless unless `gave up after N tries` appears; then raise `max_retries` or `retry_base_wait` |
| `ray.exceptions.RayActorError` | The episode returns as an errored, masked-out row and the actor restarts (`max_restarts=-1`) | Check `ray logs` and per-node memory ([Ray Cluster](../../../infrastructure/ray.md#monitoring)) |
| `SweEnvironment has nothing to grade against` at environment construction | `requires_answer: false` with no `test_function` while the reward prices the environment's grade | Grade against an `answer` column, pass a `test_function`, or price the episode with external terms only ([SWE → Reward](../environments/swe-environment.md#reward)) |
| `bubblewrap sandbox runs the jail's root as a subordinate uid` at environment construction | The image lacks `uidmap` or a subordinate range for root, or the trainer does not run as root | Use the training image, which ships both, as root ([Sandboxes](../environments/sandbox.md#choosing-a-backend)) |
| `bubblewrap's jail cannot reach a path it binds` at environment construction | `TMPDIR` or a directory above it is private, and the jail's root is not this process's uid | Point `TMPDIR` at a directory every user can search, as `/tmp` is ([Sandboxes](../environments/sandbox.md#choosing-a-backend)) |
| `bubblewrap cannot mount the jail's /proc` at environment construction | The container's `/proc` has masks over parts of it (Docker's; in a GPU container, the NVIDIA runtime's), so the kernel refuses the jail a fresh one | Mount a clean proc beside it before the trainer starts: `mkdir -p /run/fullproc && mount -t proc proc /run/fullproc` ([Sandboxes](../environments/sandbox.md#choosing-a-backend)) |
| `the local sandbox waits on its programs through pidfd_open, which this environment refuses` at environment construction | The `local` / `bubblewrap` sandbox waits on every run through a pidfd, which the kernel (before 5.3) or the container's seccomp profile refuses | Run on Linux 5.3+ with `pidfd_open` allowed, or set `sandbox_backend: remote` ([Sandboxes](../environments/sandbox.md#choosing-a-backend)) |
